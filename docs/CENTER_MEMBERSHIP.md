# 센터 회원가입·마스터 승인 작업

홈은 회원 로그인/가입 화면이다. 기관코드와 이름, 이메일, 본인이 정한 비밀번호로 신청한다. Supabase Auth 이메일 확인과 마스터 승인 전에는 일반 계정 로그인을 거절한다. 신청 역할은 권한을 부여하지 않는다. 일반 관리자는 승인할 수 없으며 서버에 설정한 마스터만 같은 기관의 대기 신청을 승인/반려한다. 관리자 수는 두 명으로 제한하지 않는다.

## 운영 준비

- db/migrations/2026-10-20-center-membership.sql을 기존 Supabase에 적용하고 기관코드/기관명을 center_organizations에 등록한다. 현재 자동 적용하지 않았다.
- Supabase Auth의 이메일 확인과 사이트 URL/허용 redirect 구성을 운영 주소로 확인한다. 비밀번호는 Supabase Auth에 의해 관리된다.
- .env.local.example의 CENTER_ 서버 환경변수를 배포 환경에 설정한다. 마스터 비밀번호는 bcrypt 해시만 저장한다. 실제 계정 주소/비밀번호는 커밋하지 않는다. 마스터 초기 비밀번호의 자동 입력은 실행 정책에서 거절돼 완료하지 못했다.
- 일반 사용자 승인은 /center의 회원승인에서 마스터가 처리한다. 요양보호사 승인은 기존 참여자코드와 연결하고 CENTER_LEGACY_ORGANIZATION_CODE와 같은 기관일 때만 기존 /care 데이터에 접근한다. 다른 기관에는 기존 파일럿 데이터를 노출하지 않는다.
- 센터 직원/수급자/일정 화면은 아직 탭 메모리 기반 UI 검토본이다. 업무 DB 영구 저장/파일 보관/급여 계산/공단 연동은 구현되지 않았다.

## 검증과 한계

마스터 인증, 일반 관리자 승인 금지, 승인 대기·정지·미인증 차단, 세션 재검증, 기관 경계의 단위 검증을 추가했다. 운영 DB/메일/실사용 계정의 통합 검증과 새 UI의 브라우저 검증은 미완료다. 로컬 서버 시작은 확인했지만 브라우저 접근에 실패했다. 운영 배포 완료를 의미하지 않는다.

UI 근거는 사용자가 허용한 이지케어 화면 조회다. REA로 분석한 것은 공개 가입 확인 스크립트 한 개이며 전체 시스템/서버 코드 복원이 아니다.

검토 경로: /center?demo=1. 실제 기관 데이터·회원 API에 연결하지 않는 메모리 기반 화면 검토다. /api/center/:action은 vercel.json에서 기존 /api/admin/session으로 연결해 기존 함수 개수를 유지한다. 최신 기관 접근 제어는 보존했다.
