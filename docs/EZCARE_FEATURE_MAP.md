## 0. 이 문서의 목적과 읽은 범위

**목적(사용자 지시 2026-10-01)**: 이지케어를 분석해 기능을 파악하고, **AI를 접목하면 더 나아질 부분**을 찾아 이 앱에서 만들어 본다.
그래서 기능 나열보다 §3 "사람이 손으로 쓰고·대조하고·확인하는 곳 = AI 후보"를 중심으로 썼다. 기능 구조와 업무 흐름을 분석했고, 도움말 문장·화면을 그대로 옮기지는 않았다.

**읽은 범위(정직하게)**
- 도움말 14개 분류, 글 222건의 **제목은 전부** 확인했다.
- 본문은 **13건만** 읽었다: 요양보호사 앱 주요 메뉴 · 업무수행일지 작성 · 업무수행일지 전자서명 · 서류작성 및 결재 · 직원변경 상담일지 · 일정확정 가이드 ·
  계획일정과 청구일정의 차이 · 공단 본인부담금 비교 · 태그 전송 내역 확인 · 수급자 변경내역 공단 연동 · 활용 가이드[운영편] · 수급자 관리일 · 인지기능검사 CIST.
  나머지 209건은 제목만 근거로 분류했으므로 세부 동작은 단정하지 않는다.
- 이지케어 프로그램 화면 자체(로그인 후)는 이 환경에서 볼 수 없다. 사용자가 보내 준 화면 캡처에 일부가 보였을 뿐이다.
- 이 앱 쪽은 MASTER_CONTEXT.md / CHANGE_LOG.md 기준이며 코드를 다시 분석하지 않았다.

## 1. 이지케어의 뼈대: 공단 자료에서 시작해 청구·급여로 흘러간다

```
공단에서 수급자·일정 가져오기 → (계획일정 = 안내용) → 청구일정 가져오기(RFID 태그 반영) → 일정확정
   → 본인부담금(청구·수납·CMS·현금영수증·문자) + 직원 급여(주휴·연차·4대보험·퇴직금)
   → 서류함(평가 서류·결재) · 서식 출력
```
핵심 약속은 "한 번 입력한 정보가 청구까지 이어진다"이다. 일정확정 전에 공단 청구 금액과 대조하는 절차가 가장 중요한 관문이다(확정 후에는 수정이 어렵다).
