# 이지케어 기능 지도 (공개 소개 페이지 기준) vs AI365 CARE DREAM

작성일: 2026-10-01 · 출처: https://ezcare.easyms.co.kr 의 공개 소개 페이지 5개
(`/index.html?PG=visit` 방문요양, `PG=daycare` 주간보호, `PG=w4c` 재무회계, `PG=addition` 부가서비스, 메인 `/`).

## 읽은 범위와 한계 (먼저 읽을 것)

- **요청하신 주소 `new.ez`는 로그인이 필요한 화면**이라 열리지 않는다(자동 로그아웃 안내 화면으로 이동). `/help/`도 접근이 거부(403)됐다.
  즉 **도움말 본문(메뉴별 사용법)은 읽지 못했다.** 아래 지도는 로그인 없이 공개된 소개 페이지의 기능 설명만 근거로 한다.
- 소개 페이지는 홍보 문구라서 화면 구성·입력 항목·세부 규칙은 알 수 없다. 도움말 본문을 읽으면 §4의 빈칸을 채울 수 있다.
- 비교 대상인 이 앱의 기능은 MASTER_CONTEXT.md / CHANGE_LOG.md 기준이며, 이번에 코드를 다시 분석하지 않았다.

## 1. 이지케어 한눈에

이지케어는 **재가장기요양기관 운영 전체(일정·청구·급여·회계·평가)를 관리하는 ERP**다. 중심 자료는 공단에서 불러온 수급자이고,
업무가 "수급자 등록 → 일정·직원 배정 → 급여제공기록 → 청구·수납 → 평가·운영"으로 이어진다.
이 앱은 그와 달리 **현장 말하기 → AI 확인 → 관리자 검토 → 현장 후속** 한 가지 흐름에 집중한다.

## 2. 이지케어 기능 지도

### A. 방문요양 ERP
| 영역 | 기능 |
|---|---|
| 수급자·요양보호사 관리 | 기본정보, 인정등급 기간, 서비스 이력, 급여·수납 정보 |
| 방문일정 관리 | 달력에서 방문일정 등록, 요양보호사 배정, 일정표 확인 |
| 급여제공기록 관리 | 일정 기준 제공 기록 |
| 청구·수납 | 본인부담금 청구 내역·수납 여부, CMS 자동이체, 현금영수증 |
| 요양보호사 급여 | 근무내역, 4대보험, 주휴·연차수당, 급여명세서 전달 |
| 모바일 앱 연계 · 문자 발송 | (소개 페이지에 제목만 있음) |
| 평가·운영 지원 | 일·주·월·분기·연 업무주기별 운영 매뉴얼, 평가 자가진단, 80여 종 업무 서식 |

### B. 주간보호 ERP (방문요양과 겹치는 부분 제외)
| 영역 | 기능 |
|---|---|
| AI 기반 수급자 관리 | 수급자 **상태 변화 기록을 분석해 급여제공계획서 자동 생성**, 판단 근거 작성 지원 |
| 일정·송영 | 이용일정, 차량 운행(송영), 출결 변동, 직원 배정 |
| 프로그램 일정·급여제공 기록 | 연간계획에 따른 계획 수립, **평가기준 준수 여부 자동 검증** |
| AI 서류 생성 | 운영규정·재난대응 매뉴얼 등 기관 필수 문서 작성 지원, 기록 누락 점검 |
| AI 회계 처리·보고 | 결의서 초안 자동 생성, 잔액·예산·오류 감지, 희망이음 자동 등록 (**'26년 10월 출시 예정**) |
| 24시간 AI 상담 | 고객 지원 |

### C. 재무회계 대행
회계(월 결의서·예산·결산·추경·장부), 세무(원천세·간이지급명세서·퇴직금·연말정산), 사회보험(취득·상실·보수총액·휴복직 신고, 신고 대상 알림), 노무(1:1 상담, 근로계약서 검토).

### D. 부가서비스
인지활동북(자료·월간계획표) · 요양보호사 구인구직 · 공동구매 · 본인부담금 자동이체 · 통장거래내역 조회 · 현금영수증 발급.

## 3. 이 앱(AI365 CARE DREAM)과의 대응

| 이지케어 기능 | 이 앱의 대응 | 판단 |
|---|---|---|
| 수급자 관리(기본정보·담당) | 관리자 '수급자 관리'(등록·수정·담당 배정·활성 전환, 운영 DB 적용 대기) + 수급자 상세 | 겹침. 이 앱은 청구·등급 기간 없이 **돌봄 기록 중심** |
| 요양보호사 배정 | 담당 요양보호사 배정/변경 | 겹침(일정 없이 "담당" 단위) |
| 수급자 상태 변화 기록 → 계획서 | 말하기 → AI 확인(질문·요약) → 변화 후보·관찰 달력·반복 보고 후보 | **가장 가까운 지점.** 이지케어는 기록→계획서 자동 생성, 이 앱은 기록→관리자 판단·조치. 계획서 생성은 없음 |
| 평가 자가진단·누락 점검 | 표준화 척도 13종 실시·채점, 사전·사후 이력, 운영 지표('실증과 품질') | 목적이 다름: 기관 평가 준비 vs 수급자 변화 측정 |
| 방문일정·송영·출결 | 없음 | 이 앱 범위 밖 |
| 급여제공기록 | 돌봄기록(말하기 보고) | 형식이 다름 — 정해진 서식 vs 말로 한 보고를 AI가 정리 |
| 청구·수납·급여·회계·세무·노무 | 없음 | 이 앱 범위 밖 |
| 인지활동북 | 없음 | 범위 밖 |
| 업무 매뉴얼·서식 80종 | 없음 | 범위 밖 |
| 관리자 업무 현황 | '오늘의 돌봄' 업무 카드, 요청과 후속조치, 기한·안전 검토 | 이지케어에는 소개되지 않은 **이 앱 고유 흐름**(관리자 판단→현장 인계→다음 방문 응답→재확인) |
| 음성 입력·AI 질문·전송 동의 | 요양보호사 /care 화면 | 소개 페이지에 음성 보고 기능은 없음 — **이 앱의 차별점** |

## 4. 도움말 본문을 읽으면 채울 빈칸

- 상태 변화 기록의 입력 방식(서식인지 자유 서술인지)과 AI 계획서 생성의 결과물 모양
- 모바일 앱에서 요양보호사가 실제로 하는 일(출퇴근 기록? 서비스 기록?) — 이 앱 /care와 직접 비교할 부분
- 관리자 알림·미확인 업무 목록이 있는지

## 5. 이 지도에서 얻은 시사점 (판단은 기획자 몫)

1. 이지케어가 AI로 하는 일은 **서류 자동 작성**이고, 이 앱은 **현장 말을 구조화해 관리자 판단을 돕는 것**이다. 같은 AI라도 목적이 달라 정면 경쟁 영역이 좁다.
2. 반대로 현장 관리자는 이미 이지케어 같은 ERP를 쓴다. 연동(수급자 목록 가져오기 등)이 없으면 수급자를 두 번 입력하게 된다 — 도입 시 부담 요인.
3. 가장 겹치는 곳은 '수급자 상태 변화 → 후속 문서/조치'다. 이 앱이 어디까지 책임질지(조치까지? 계획서까지?)는 별도 결정이 필요하다.
